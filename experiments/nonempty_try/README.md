# Експеримент: вартість try у NonEmpty (п. 35 документа архітектури)

**Питання.** З v4.10 у fn_ApplyRulesEx кожен рядок перевіряється на порожнечу всередині `try … otherwise true`, щоб клітинка-помилка не ламала запит. Скільки це коштує на робочих даних (GO3 — 81 тис. рядків)?

**Як міряємо.** Два варіанти поруч в одному запуску профайлера, бо розкид між запусками ±20–30% (розділ 6.12):

| Поточний (з try) | Без try (як у v4.9) |
| --- | --- |
| pq_QualitySummary | pq_QualitySummary_nt |
| q_GO | q_GO_nt |

Ланцюжки `_nt` — копії поточних функцій, що відрізняються лише рядком NonEmpty у fn_ApplyRulesEx_nt:
- звіт: fn_ApplyRulesEx_nt → fn_SchemaReport_nt → fn_RowReport_nt → fn_QcReports_nt → pq_QualitySummary_nt;
- завантаження: fn_ApplyRulesEx_nt → fn_ApplyRules_nt → fn_EnforceSchema_nt → fn_ReadPurpose_nt → q_GO_nt.

Варіант без try на робочих даних безпечний: у них немає клітинок-помилок. Але в робочий код він не годиться.

## Кроки

1. GitHub Desktop: Current branch → `experiment/nonempty-try` → Pull. **Робоча книга** (з даними).
2. ImportPQQueriesFromFolder → `D:\GitHub\PQ_Engine\experiments\nonempty_try`. Має бути створено 9 запитів.
3. pq_QualitySummary_nt і q_GO_nt — «Завантажити до…» → таблиця на **новому** аркуші (кожен на своєму). pq_QualitySummary і q_GO мають бути на аркушах, як і зараз.
4. Умови: ноутбук від мережі, режим «Найкраща продуктивність», інші програми закриті.
5. ProfilePowerQueries з прогрівом — **3 запуски** поспіль.
6. Надішліть рядки PQ_Profiler для цих 4 запитів (разом із колонкою Seq).
7. Після заміру: видалити 9 запитів `_nt` і їхні аркуші, перемкнутися на `main` (Discard changes, якщо експорт щось записав). ExportPowerQueriesToRepo **з `_nt`-запитами в книзі не запускати** — вони потрапили б у powerquery\queries.

## Як читати

Порівнювати пари в межах одного запуску (співвідношення з try / без try):
- ≤ 1,05 у всіх запусках — try практично безкоштовний, лишається (рішення v4.10 підтверджено);
- стабільно > 1,10 — шукати дешевший спосіб захисту від клітинок-помилок (наприклад, try лише навколо Text.Trim) і міряти знову.

Pull request цієї гілки не зливати: результат запишеться в документ окремим комітом, а експеримент закриється.
